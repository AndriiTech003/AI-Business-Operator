# 06 · AI Business Operator

> AI-агент, который **реально выполняет работу** в бизнес-системе (проект 05) через MCP-инструменты, но под контролем: политика прав, одобрение человеком для рискованных действий, защита от prompt injection, полный аудит и **eval-набор сценариев в CI**.

Пример:

> «Найди лидов, которым не отвечали больше 7 дней, и подготовь им follow-up письма.»

```text
list_contacts(status=lead, lastContactedBefore=7d)         → 23 лида            [auto: read]
get_contact × 23 (история переписки)                         → контекст          [auto: read]
draft_email × 23 (dryRun → превью)                           → 23 черновика      [auto: reversible]
send_email × 23                                              → ⏸ approval batch  [policy: external]
  └─ человек отмечает 19 из 23, правит 2 письма, Approve
send_email × 19 (ровно одобренные payload'ы)                 → отправлено
create_task × 4 («позвонить», для тех, кому письмо не ушло)  → [auto: reversible]
Итог: отчёт + ссылки на записи, стоимость $0.07, 31 шаг
```

## Что отличает от «чат-бота с function calling»

| Типичный AI-агент | Этот проект |
|---|---|
| Модель вызывает что угодно | **Policy engine**: права пользователя ∩ политика агента; запрещённые инструменты модель даже не видит |
| «Вы уверены?» в чате | **Approval-карточки** с превью (отрендеренное письмо, diff полей), пакетное одобрение, правка перед отправкой; **выполняется ровно то, что одобрено** (hash payload) |
| Доверяет данным | Данные из инструментов — недоверенные; **taint-проверка**: аргумент действия, взятый из недоверенного текста, требует одобрения с предупреждением |
| Цикл до бесконечности | Бюджеты: шаги, токены, $, время; идемпотентные ключи на каждое действие |
| Состояние в памяти | **Durable runs**: ожидание одобрения может длиться днями, сервис можно перезапустить |
| «Работает на моём промпте» | **Eval-сценарии** с проверкой конечного состояния системы, red-team набор, record/replay LLM-ответов в CI, сравнение моделей |
| Чёрный ящик | Таймлайн каждого запуска: вызовы модели, инструменты, решения политики с id правила, стоимость |

## Связь с другими проектами

- Инструменты — MCP-сервер `ops-mcp` из **проекта 05**. Агент ходит через него с токеном пользователя, поэтому права бизнес-системы соблюдаются автоматически.
- Одобрения отображаются в общем **Approvals inbox** проекта 05 (`source: agent`) и в собственной консоли агента.
- Политика использует **язык выражений `@scope/expr`** из проекта 05 (переиспользование пакета между репозиториями).
- Плейбуки по расписанию можно вызывать из workflow проекта 05 (узел `ai_step`).

## Главные гарантии

1. Агент **никогда** не выполняет действие, запрещённое политикой или не разрешённое правами пользователя (тест + eval-gate: violations = 0).
2. Действие, требующее одобрения, выполняется **только с одобренным payload** (совпадение hash); изменить его после одобрения нельзя.
3. Повтор выполнения (сбой, рестарт) не дублирует эффекты: у каждого действия свой idempotency key.
4. Запуск не выходит за бюджет (шаги, токены, $, время) и корректно завершается с отчётом о том, что успел.
5. Инструкции внутри данных (письмо лида, заметка) не исполняются как команды (red-team сценарии в CI).
